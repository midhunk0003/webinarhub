# CLAUDE.md

Architecture and conventions for this Flutter app. Follow these rules exactly when adding features, so every feature looks like every other feature.

## Stack

- **Flutter** (Dart SDK ^3.7), Material
- **State:** `provider` (`ChangeNotifier` + `MultiProvider`)
- **DI:** `get_it` (manual registration, no `injectable` codegen at runtime)
- **Functional errors:** `dartz` → every repository method returns `Future<Either<Failure, T>>`
- **HTTP:** `http` package wrapped by a single `ApiClient`
- **JSON:** `json_annotation` + `json_serializable` + `build_runner` (`*.g.dart` files are generated, never hand-edited)
- **Local storage:** `shared_preferences` (session/user info), `flutter_secure_storage`
- **UI helpers:** `flutter_svg`, `shimmer`, `lottie`
- **Push:** `firebase_core`, `firebase_messaging`, `flutter_local_notifications`

## Commands

```bash
flutter pub get
dart run build_runner build --delete-conflicting-outputs   # after adding/changing any model
flutter analyze
flutter run
```

## Layered architecture (Clean-ish, 3 layers)

```
Screen (UI)  ──reads/calls──▶  Provider (ChangeNotifier)
                                   │ depends on abstract
                                   ▼
                          domain/repository (abstract class)
                                   ▲ implemented by
                                   │
                    data/repository_impl  ──uses──▶ ApiClient ──▶ REST API
                                   │
                                   └──parses into──▶ data/model (json_serializable)
```

Dependency direction is strictly downward:
- **presentation** imports `domain` (abstract repos), `data/model`, and `core`. It never imports `ApiClient` or a repository implementation.
- **domain** contains only abstract repository contracts. It imports `core/failure.dart`, `core/success.dart`, and models.
- **data** implements domain contracts and owns networking, local storage, and models.
- **core** has no dependency on features. The exceptions are `ApiClient` → `NavigationService`/`AppSnackBar`, used for forced logout.

There is no separate use-case layer. Providers call repositories directly.

## Naming conventions

| Thing | File | Class |
|---|---|---|
| Repository contract | `<feature>_repository.dart` | `abstract class <Feature>Repository` |
| Repository impl | `<feature>_repo_impl.dart` | `class <Feature>RepoImpl implements <Feature>Repository` |
| Model | `<feature>_model/<feature>_model.dart` | `class <Feature>Model` |
| Provider | `<feature>_provider.dart` | `class <Feature>Provider extends ChangeNotifier` |
| Screen | `<name>_screen.dart` / `<name>_page.dart` | `class <Name>Screen` |
| Endpoint const | in `ApiEndPoint` | `static const String <name>EndPoint = "Path/sub";` |
| Route name | in `main.dart` | lowercase, no separators: `'/paymenthistoryscreen'` |

Files use snake_case and classes use PascalCase. Prefix role-specific items with `trainer`/`user`.

## Core contracts

### Failure / Success (`core/failure.dart`, `core/success.dart`)

```dart
abstract class Failure { String? message; int? statusCode; ... }
class ServerFailure extends Failure       // 5xx
class ClientFailure extends Failure       // 4xx (first validation error from `errors` map, else `message`)
class AuthFailure extends Failure         // 401 / session expired
class NetworkFailure extends Failure      // SocketException / timeout
class LoginFailure extends Failure
class OtherFailureNon200 extends Failure  // bad JSON, unknown status
class EmptyFailure extends Failure

class Success { final String message; }   // for mutations that return nothing useful
```

### ApiClient (`data/network/api_client.dart`)

- Methods: `get`, `post`, `put`, `patch`, `delete`. Each returns `Future<Either<Failure, Map<String, dynamic>>>`.
- Parameters: `url` (full URL), `body` (`Map`, JSON-encoded), `files` (`Map<fieldName, filePath>`; this switches the request to multipart), `requiresAuth` (default `true`).
- Adds the `Authorization: Bearer <accessToken>` header (token read from SharedPreferences key `accessToken`).
- **On 401:** calls `_refreshToken()` (POST `refreshTokenEndPoint` with `refreshToken`) and retries once. If the refresh fails, it calls `_forceLogout()`, which clears the session, navigates to `/loginscreen` through `NavigationService.navigatorKey`, and shows a snackbar.
- `handleResponse()` maps HTTP status codes to the Failure subclasses above. A 2xx response returns `Right(decodedJson)`.
- Timeouts are 20–30 s. Timeouts and `SocketException` map to `NetworkFailure`.

### Standard API response envelope

```json
{ "statusCode": 200, "success": true, "message": "...", "errorCode": null, "data": {...} | [...], "errors": null, "details": null }
```

Every top-level model mirrors this envelope, and `data` is typed to a nested model.

## How to add a new feature (end-to-end recipe)

Example: a "notifications" feature for the user role.

**1. Endpoint:** add it to `core/api_end_point.dart`:
```dart
static const String notificationEndPoint = "Notifications/me";
```

**2. Model:** create `data/model/notification_model/notification_model.dart`:
```dart
import 'package:json_annotation/json_annotation.dart';
import 'package:<app>/core/json_converter.dart';

part 'notification_model.g.dart';

@JsonSerializable()
class NotificationModel {
  @JsonKey(fromJson: stringFromJson) String? statusCode;
  @JsonKey(fromJson: stringFromJson) String? success;
  @JsonKey(fromJson: stringFromJson) String? message;
  @JsonKey(fromJson: stringFromJson) String? errorCode;
  List<NotificationItem>? data;
  dynamic errors;
  dynamic details;

  NotificationModel({this.statusCode, this.success, this.message, this.errorCode, this.data, this.errors, this.details});

  factory NotificationModel.fromJson(Map<String, dynamic> json) => _$NotificationModelFromJson(json);
  Map<String, dynamic> toJson() => _$NotificationModelToJson(this);
}
```
Model rules: **all fields nullable**. Scalar fields use `@JsonKey(fromJson: stringFromJson)` so a number, bool, or string from the backend never crashes parsing. Nested classes go in the same file. Then run `build_runner`.

**3. Contract:** add `domain/repository/user_repo/user_notification_repository.dart`:
```dart
abstract class UserNotificationRepository {
  Future<Either<Failure, NotificationModel>> getNotifications();
  Future<Either<Failure, Success>> markAsRead(String? id);
}
```

**4. Implementation:** add `data/repository_impl/user_repo_impl/user_notification_impl.dart`:
```dart
class UserNotificationImpl implements UserNotificationRepository {
  final ApiClient apiClient;
  UserNotificationImpl({required this.apiClient});

  @override
  Future<Either<Failure, NotificationModel>> getNotifications() async {
    try {
      final result = await apiClient.get("${ApiEndPoint.baseUrl}${ApiEndPoint.notificationEndPoint}");
      return result.fold(
        (failure) => Left(failure),
        (data) => Right(NotificationModel.fromJson(data)),
      );
    } catch (e) {
      return Left(OtherFailureNon200(e.toString()));
    }
  }
}
```
Implementation rules: build the full URL as `baseUrl + endpoint (+ "/$id")`, `fold` the ApiClient result, parse the success branch with `Model.fromJson`, and wrap the whole method in try/catch. Mutations return `Right(Success(message: model.message ?? "fallback"))`.

**5. Provider:** add `presentation/provider/user_provider/user_notification_provider.dart`:
```dart
class UserNotificationProvider extends ChangeNotifier {
  final UserNotificationRepository userNotificationRepository;
  UserNotificationProvider({required this.userNotificationRepository});

  bool _isLoadingNotifications = false;
  Failure? _failure;
  Success? _success;
  NotificationModel? _notificationModel;

  bool get isLoadingNotifications => _isLoadingNotifications;
  Failure? get failure => _failure;
  Success? get success => _success;
  NotificationModel? get notificationModel => _notificationModel;

  void clearFailure() { _failure = null; notifyListeners(); }
  void clearSuccess() { _success = null; notifyListeners(); }

  Future<void> getNotificationsPro() async {
    _isLoadingNotifications = true;
    _failure = null;
    _success = null;
    notifyListeners();

    final result = await userNotificationRepository.getNotifications();
    result.fold(
      (failure) => _failure = failure,
      (data) => _notificationModel = data,
    );
    _isLoadingNotifications = false;
    notifyListeners();
  }
}
```
Provider rules:
- Keep private fields with public getters.
- Use **one `_isLoadingXxx` flag per API call**.
- Keep a single `_failure` and a single `_success` per provider.
- Every API method follows the same sequence: set loading, clear failure and success, notify, await the repository, fold, clear loading, notify.
- Every provider exposes `clearFailure()` and `clearSuccess()`.
- Pure UI state (tab index, toggles, selection mode) also lives in the provider.

**6. DI:** register in `core/dependency_injection.dart`:
```dart
getIt.registerLazySingleton<UserNotificationRepository>(
  () => UserNotificationImpl(apiClient: getIt<ApiClient>()),
);
getIt.registerFactory<UserNotificationProvider>(
  () => UserNotificationProvider(userNotificationRepository: getIt<UserNotificationRepository>()),
);
```
Registration order is: infrastructure (http.Client, SharedPreferences, SecureStorage, LocalDataSource, ApiClient), then repositories as `registerLazySingleton<Abstract>`, then providers as `registerFactory`.

**7. Provide it:** add it to `MultiProvider` in `main.dart`:
```dart
ChangeNotifierProvider(create: (_) => getIt<UserNotificationProvider>()),
```
A provider with no dependencies (pure UI state) can be constructed directly: `ChangeNotifierProvider(create: (_) => OnboardProvider())`.

**8. Route:** add a case to `onGenerateRoute` in `main.dart`:
```dart
case '/usernotificationscreen':
  return _customPageRoute(UserNotificationScreen());
case '/somedetailpage':                       // with arguments: always a Map<String, dynamic>
  final args = settings.arguments as Map<String, dynamic>;
  return _customPageRoute(SomeDetailPage(courseId: args["courseId"]));
```
`_customPageRoute` is a `PageRouteBuilder` with no transition (`Duration.zero`). Navigate with `Navigator.pushNamed(context, '/route', arguments: {...})`.

**9. Screen:** use this standard screen skeleton:
```dart
class UserNotificationScreen extends StatefulWidget { ... }

class _UserNotificationScreenState extends State<UserNotificationScreen> {
  bool _isDialogShowing = false;

  @override
  void initState() {
    super.initState();
    WidgetsBinding.instance.addPostFrameCallback((_) => _initialData());
  }

  Future<void> _initialData() async {
    if (!mounted) return;
    final provider = context.read<UserNotificationProvider>();
    await Future.wait([provider.getNotificationsPro()]);   // multiple calls in parallel
  }

  void _handleFailure(UserNotificationProvider provider) {
    if (_isDialogShowing || provider.failure == null || !mounted) return;
    if (provider.failure is NetworkFailure) return;        // handled inline by NetWorkRetry
    _isDialogShowing = true;
    AppDialogHelper.showFailureDialog(
      context: context,
      failure: provider.failure,
      provider: provider,
      onTap: () { provider.clearFailure(); Navigator.pop(context); },
    );
    _isDialogShowing = false;
  }

  @override
  Widget build(BuildContext context) {
    return Reusablebackground(
      child: SafeArea(
        child: LayoutBuilder(builder: (context, constraints) {
          final bool isTablet = constraints.maxWidth > 600;
          return Consumer<UserNotificationProvider>(builder: (context, provider, _) {
            if (provider.failure is NetworkFailure) {
              return NetWorkRetry(
                failureMessage: provider.failure?.message ?? "No internet connection",
                onRetry: _initialData,
              );
            }
            if (provider.isLoadingNotifications) return const SomeShimmer();
            final items = provider.notificationModel?.data ?? [];
            if (items.isEmpty) return const CommonEmptyState(...);
            return ListView(...);
          });
        }),
      ),
    );
  }
}
```
Screen rules:
- Load data in `addPostFrameCallback`.
- Use `context.read` for calls and `Consumer` for rebuilds.
- Show `NetworkFailure` inline with `NetWorkRetry`. Show every other failure in a dialog through `AppDialogHelper`.
- The UI order is: loading (shimmer), then empty state, then content.
- **Responsive:** get `isTablet` from `constraints.maxWidth > 600` and branch sizes with `isTablet ? a : b`.
- Wrap every full screen in `Reusablebackground`.
- Use `CommonCustomAppBarWidget` for the header.
- Split large screens into private `_buildXxx(bool isTablet)` methods. Move a section into its own file under `widgets/` once it is reused or grows large.

## App flow and auth

1. `main()`: `WidgetsFlutterBinding.ensureInitialized()`, then `setupDependencyInjection()` with a 15 s timeout. If DI fails, it shows a fallback "initialization failed" app. Otherwise it runs `runApp(MyApp)` and **then** initializes Firebase/FCM, so Firebase never blocks the first frame.
2. **Splash** (`/`) reads SharedPreferences: `onboard`, `role`, `accessToken`.
   - Onboarding not done → `/onboardscreen`
   - Token and role present → `/custombottomnavbarwidget` with `{'userrole': role}`
   - Otherwise → `/loginscreen`
3. **Login:** `AuthLocalDataSource.saveUserData(LoginModel)` stores `userid`, `accessToken`, `refreshToken`, `role`, `fullName`, `email`, and more in SharedPreferences.
4. **Role shell:** `CustomBottomNavbarWidget(userRole)` switches on role (`trainer` / `client`) to build a role-specific list of `BottomNavItem(page, icon)`.
5. **Logout / session expiry:** `AuthLocalDataSource.clearSession()` wipes secure storage and prefs but **keeps the `onboard` key**. It then navigates with `NavigationService.navigateToLogin()`.

## Styling

- All colors come from `AppColor` (`core/colors.dart`) as `static const Color`s and gradient lists (`AppColor.darkGradient`). Never hardcode hex values in widgets.
- The theme is dark with gold accents. Fonts are declared in pubspec (`AfacadFlux`, `Urbanist`) and referenced by `fontFamily`.
- Icons are SVGs rendered with `SvgPicture.asset`. Every asset must be listed in `pubspec.yaml` under `flutter: assets:`.
- Loading UI uses `shimmer` skeletons from `presentation/widgets/shimmer_widgets/`, not bare spinners, for lists and sections.
- Feedback goes through `AppSnackBar.show(context, message:, color:, icon:)` and `AppDialogHelper.showSuccessDialog` / `showFailureDialog`.

## Don't copy these from the original project

The source project has some habits that should not carry over:
- **Typos in names:** the original has `repository_implimentation`, `local_data_sourse`, `diloges`, `dependence_injection`, and `*Implimentation`. Use the corrected names shown above.
- **Leftover debug output:** the original has `print()` calls with junk strings. Use `debugPrint` or `log` and keep them out of committed code.
- **Duplicated retry code:** the 401 refresh-and-retry logic is copied into every HTTP method. Factor it into one private `_send()` helper.
- **Token storage:** tokens live in SharedPreferences even though `flutter_secure_storage` is registered. Put tokens in secure storage.
- **Hardcoded base URL:** the base URL is a hardcoded `http://` IP. Use `--dart-define` or flavors per environment, and HTTPS.
- **Dead files:** remove `*_old.dart` files and commented-out blocks instead of keeping them around.
- **`DevicePreview`:** it wraps the app in `main.dart`. Keep `enabled: false` (or `!kReleaseMode`) in production.
